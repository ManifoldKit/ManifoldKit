# UnlockedNonisolatedUnsafeTestSeamAuditTest — path-based allowlist.
#
# `nonisolated(unsafe) static var` is not itself one of CLAUDE.md's six
# originally-documented Swift 6 concurrency gotchas (it's now the 7th), so an
# unguarded static test-injection seam had no other checklist protection.
# Three real ones shipped before this audit existed (see issue #2094):
# `DNSRebindingGuard._resolverForTesting`,
# `RedirectGuardDelegate._synchronousResolverForTesting`, and four hooks on
# `GenerationQueue`. All three are now lock-guarded via a computed property +
# private backing store and no longer appear here as unguarded declarations
# (though the DNSRebindingGuard/RedirectGuardDelegate backing storage vars
# still carry `nonisolated(unsafe)` by necessity — see the "Lock-guarded"
# section below — the same shape `MCPSSRFPolicy` already used correctly).
#
# Every entry below was read and verified at review time to be either:
#   (a) demonstrably lock-guarded — every read/write of the backing store
#       goes through a Lock (NSLock/OSAllocatedUnfairLock) in the same file, or
#   (b) a genuinely write-once-before-any-reader flag with a doc comment
#       explaining the boot-time contract.
#
# Format: one fingerprint per line, of the form
#   <relative path under Sources/>:<trimmed source line>
#
# - Empty lines and `#`-prefixed lines are ignored.
# - Entries must match the audit's fingerprint EXACTLY (the line content is
#   the trimmed source line, not a regex).
#
# DO NOT add entries to make a failing test pass without actually verifying
# the declaration is lock-guarded or genuinely write-once. If it's neither,
# fix it — don't allowlist it.

# ---------------------------------------------------------------------------
# Lock-guarded — every read/write goes through a Lock in the same file
# ---------------------------------------------------------------------------

# _pinnedHosts and _defaultPinsLoaded are both guarded by the adjacent
# _pinnedHostsLock (NSLock) — every access path (pinnedHosts getter/setter,
# loadDefaultPins(), resetDefaultPinsForTesting()) locks first.
ManifoldCloudCore/PinnedSessionDelegate.swift:private nonisolated(unsafe) static var _pinnedHosts: [String: Set<String>] = [:]
ManifoldCloudCore/PinnedSessionDelegate.swift:private nonisolated(unsafe) static var _defaultPinsLoaded = false

# Guarded by the adjacent overrideLock (NSLock) via the _resolverForTesting /
# _synchronousResolverForTesting computed properties a few lines below each
# (the reference implementation DNSRebindingGuard/RedirectGuardDelegate now
# mirror — see issue #2094).
ManifoldMCP/MCPSSRFPolicy.swift:nonisolated(unsafe) private static var _resolverForTesting_storage: ((String) async -> [String]?)? = nil
ManifoldMCP/MCPSSRFPolicy.swift:nonisolated(unsafe) private static var _synchronousResolverForTesting_storage: ((String) -> [String]?)? = nil

# Guarded by the adjacent overrideLock (NSLock) via the _resolverForTesting

# MCPSSRFPolicy's existing pattern above.
ManifoldCloudCore/DNSRebindingGuard.swift:nonisolated(unsafe) private static var _resolverForTesting_storage: ((String) async -> [String]?)? = nil

# Guarded by the adjacent testSeamLock (NSLock) via the

ManifoldInference/Networking/RedirectGuardDelegate.swift:nonisolated(unsafe) private static var _synchronousResolverForTesting_storage: ((String) -> [String]?)? = nil
