## Part A — Root causes

### RC1. A post-1.0 process running on a pre-1.0 package (the stability ratchet)

The repo has strong machinery for *not breaking* (api-digester gate, deprecation discipline,
migration notes, companion-compat windows) and almost none for *reshaping*. Additive changes
are nearly free; reshaping costs an allowlist entry + migration note + companion window. Under
that pricing every merged design mistake is permanent-by-default.

The primary evidence is **behavioral**, not the raw growth count:

- `ManifoldBootstrap.init` appended `audioGenerationService` at the tail, out of group,
  explicitly to satisfy the source-compat digester (`ManifoldBootstrap.swift:304-307`) — a 0.x
  package contorting for a stability promise it never made.
- `GenerationConfig`'s 28-parameter init is the fossil record of one-cheap-param-per-PR accretion.
- Deletion deferred as deprecation: three 15–19-param `enqueue` builders
  (`InferenceService.swift:547,598,645`), mirrored internally in `GenerationQueue`; shadow
  typealiases held for a "1.0-adjacent" release.
- `GenerationEvent` doc says "frozen as of the 1.0 release" on a 0.65 package.

The growth numbers, **normalized** (v2 correction — the raw count overstated the story):

| tag | public types | all type decls | source LOC | public share |
|---|---|---|---|---|
| v0.20.0 | 505 | 730 | 78.6k | 69.2% |
| v0.48.0 | 766 | 1,068 | 104.6k | 71.7% |
| v0.65.0 | 890 | 1,219 | 130.5k | 73.0% |

Public types grew 76% while LOC grew 66% — a real but modest drift (public share 69%→73%),
consistent with genuine design evolution plus a mild public-by-default bias, not runaway
accretion. Sharper: the v0.48 dip was a *proportional deletion of whole subsystems* (the ratio
actually rose) — the muscle it proves is "delete retired subsystems," not "default to
non-public." RC1 stands on the behavioral evidence; the count is corroboration only.

### RC2. Visibility is a compilation outcome, not a design decision

No gate, doc, or habit asks "is this a contract?" before a declaration goes `public`. The docs
tree has written principles for QA, testing, CI economics, and companion backends — **no API
design doc exists** (verified again by two reviewers). Whatever accidentally becomes public,
the api-digester then guards, so RC1 fossilizes RC2's output.

Velocity multiplier: at ~145 PRs/14 days, largely agent-authored, each PR makes the locally
rational call; the draft-PR review loop reviews diffs, never the cumulative surface; nobody
owns the API as a whole.

Evidence: ~1,050 public types on current main; `ManifoldFuzz` exposes 97 public types,
`ManifoldTools` 69 — dev tooling with more surface than `ManifoldUI` (75). ~56 Error-conforming
types are public mostly because they cross module boundaries. Of 116 public protocols, a large
share are not consumer extension points — **but see the 2.1 caveat: "zero in-repo conformers"
does NOT mean dead**; the backend opt-in protocols' only real conformers live in the companion
repos (v2 correction).

Rory's framing sharpens the remedy: much of this surface may not belong **in MK at all** —
extraction (the proven manifold-mlx/llama shape) beats demotion for whole dev-tool products,
and sidesteps the cross-package `package`-visibility limit entirely.

### RC3. `@_exported` removed the feedback signal that keeps types in concept-correct modules

Causal story **confirmed** by git history: `ToolTypes.swift`/`BackendCapabilities.swift` landed
in `ManifoldHardware` during the P1c leaf extraction (#1610) as dependency-layering housekeeping;
CLAUDE.md's own description of Hardware's role never mentions tool types or capability flags.
The chained `@_exported`s then made placement consumer-invisible, so nothing pushed back.

**The originally proposed fix is dead** (v2 correction, reviewer-verified): Hardware's own
source uses these types load-bearingly — `StructuredOutputStrategy.swift:51-123`,
`PromptTemplate.swift:119-374`, and a real `BackendCapabilities.satisfies(...)` extension in
`GenerationCapabilityRequirement.swift:68-90`. Relocating the two files to `ManifoldContract`
(which depends on Hardware) inverts the dependency into a cycle; the honest move is a much
larger cluster relocation nobody should pay for pre-1.0.

Per Rory ("more complex than it might need to be"), RC3's remedy shrinks to **posture + truth**:
declare the products-are-the-API posture (0.3) and fix the doc comments that lie about where
types live. Placement stops being a 1.0 blocker the moment the posture is explicit.

### RC4. Layers accrete upward; nothing is demoted underneath

**Strengthened by review**: `TurnConfig`'s sampler defaults are byte-for-byte identical to
`GenerationConfig`'s (`ConversationRuntime+TurnInput.swift:31-35` vs
`InferenceBackend.swift:409-424`), its fields flow into `enqueueAsync`'s flat-parameter shape
(`ConversationTurnExecutor.swift:718-728`), and its own detailed doc comment (documenting the
real, deliberate I6 input-struct consolidation) is **silent** on the sampler re-declaration —
the duplication was not a considered tradeoff. Nine bootstrap entry points across three tiers,
none consolidated. `ConversationRuntime`'s docs still promise `send`/`regenerate`/`edit`/
`branch` shims that exist nowhere in the module.

Rory's question — "how do we maintain better design moving forward" — is answered by 0.4:
the map, the standing review question, and the member-aware surface tripwire (0.2), which
together make "does this knob already exist at another layer?" get asked at the moment a
public symbol is added.

### RC5. Two product identities — **ranked once, then the ranking rotted** (v2 reframe)

The reviewer found the identity *was* ranked: `docs/SCOPE_DECISION.md` (2026-04, self-flagged
historical) declared "a drop-in chat framework… optimized for the ChatbotUI-iOS-shaped
consumer" — and the composable-toolkit surface it deprioritized ("tool calling public API —
zero consumers") is now live and first-class at v0.65. So the defect isn't "never decided";
it's **no mechanism to notice when feature growth reverses a standing decision**. That changes
0.5 from a one-time sentence into a re-rank plus a decay-prevention hook.

CI corollary (Rory's guess, confirmed in structure): the dual identity is why two full QA
stacks exist — demo-app gates, cold-start tiers, DX walkthroughs, snippet gates test the
*framework* identity; audit/contract/tripwire suites guard the *toolkit* identity. Every PR
pays fan-out for both. Re-ranking the identity enables tiering (primary identity gates per-PR,
secondary nightly/release) — decision 0.5 has a direct CI-latency dividend.

### The unifying observation (unchanged)

The tripwire/audit culture points inward: internal invariants get executable checks; the public
contract gets prose — and prose is where drift was repeatedly proven to live (the nonexistent
shims; `GenerationConfig`'s own doc claiming 3 lossy Codable fields when the true count is 6).

What this changes:

- **Every bootstrap tier has ~1 real user; `LLM` and both `respond` spellings have zero.**
  The tiers earn their keep; the tier-1 conveniences (2.4/2.5) are cheaper to reshape than
  assumed — and `LLM`'s zero adoption among the owner's own five apps is a data point for 0.5.
- **3 of 5 apps are already broken against main** by the P7 shim retirement (they consume by
  local path/HEAD, so it surfaces at next build). The delete-don't-deprecate policy (0.1) is
  right, but its real cost lands on these apps — every wave removal ships with a migration
  note, and a one-pass local-app fix-up sweep (app-side, ~1 file each) should ride the wave.
- **The opt-in/extension protocols are consumer API, full stop**: app-side conformers exist for
  `ImageGenerationBackend`, `VideoGenerationBackend`, `TokenProvider`, `SessionToolSource`,

  include the local apps, not just the two companion checkouts.
- **`ManifoldTestSupport` has an app consumer** (idlewick) — the semver-exempt wording must say

- **`ManifoldConfiguration.shared` mutation is the de-facto config idiom** in both hand-assembly
  apps — that ambient singleton is load-bearing consumer API, not a demotion candidate.
- **Real friction is missing API, not API shape**: fireside's wait-for-idle extensions and

  June "buried/missing seams" class (Class 3) outranks surface aesthetics in consumer pain —

- **The Bootstrap injection seams get used the moment they exist** (LocalImage/idlewick inject
  services and containers) — strengthens the arch plan's 5.2 (injectable persistence pair):
  fireside's entire hand-assembly tier exists partly because store injection is missing.

## Part C — The plan (v2)

Ordering: **Phase 0 lands before Phase 2** — and Phase 0 now includes closing the digester-gate
hole, because the wave's safety net currently cannot see several of the wave's own items.

### Phase 0 — Guardrails and decisions (all S-sized or decisions)

- **0.0 Close the api-digester scope hole (NEW — hard prerequisite for any breaking work).**
  The per-PR digester covers only 5 targets (`ci.yml:226-238`) and does not follow `@_exported`;
  `ManifoldHardware` (home of `ModelType`, `ToolTypes`, `BackendCapabilities`),
  `ManifoldTestSupport`, and `ManifoldBackendTestKit` are in neither the path filters nor the
  `--targets` lists (nightly included). Consequence: arch-plan 4.1 would run the gate against
  the wrong target and go **green while missing the break**. Fix: add the missing targets +
  path filters to both `ci.yml` and the nightly backstop before any Phase-2/arch-P4 item starts.
- **0.1 Invert the ratchet (RC1).** AGENTS.md pre-1.0 policy: breaking is cheap and encouraged
  through scheduled `feat!:` waves; **pre-1.0, delete — don't deprecate** (deprecation reserved
  for post-1.0). Framed honestly per the normalization: this is about restoring reshaping
  freedom, not reversing runaway growth.
- **0.2 Make visibility a decision (RC2).** (a) AGENTS.md rule: new declarations are `package`
  unless the PR claims them as API — **with the explicit caveat that anything companions
  conform to or consume must stay `public`** (cross-package limit of `package` access).
  (b) Surface tripwire, **re-scoped**: not a type-declaration grep (member-blind — it would
  miss exactly the GenerationConfig-param accretion RC1 diagnoses, miscount `#if` branches,
  and never see macro-generated API). Use the api-digester's member-aware interface dump:
  a checked-in per-module baseline diffed in the local gate/CI; growth requires a same-PR
  baseline bump. Builds on machinery already in CI.
- **0.3 Namespace posture (RC3, simplified per Rory).** One documented sentence: *"the SwiftPM
  products are the API; module placement is internal topology."* Then fix only what bites under
  that posture anyway: the lying doc comments (Contract referencing Hardware types as native;
  the S8 shim prose) and the bare-name shadowing (2.8). **No type relocation** (cycle-verified
  infeasible as a small move).
- **0.4 `docs/API-DESIGN.md` (RC4) — the consolidation artifact for 0.1–0.5.** One page: layer
  -ownership map (which tier owns sampling / orchestration / UI policy), the visibility rule,
  the pre-1.0 delete policy, identity ranking (from 0.5). Plus the **standing review question**
  added to the /ship reviewer brief: "does this diff add a public symbol or knob, and does that
  knob already exist at another layer?"
- **0.5 Re-rank the identity (RC5, reframed).** SCOPE_DECISION.md ranked it in 2026-04
  (framework-first); feature growth reversed it silently. Re-rank now, record it in
  API-DESIGN.md, and add the decay hook: any PR that adds a new public surface to the
  *secondary* identity cites the ranking in its body. CI dividend: the ranking licenses QA
  tiering (primary-identity gates per-PR; secondary nightly/release) — worth scoping separately
  once decided.

## Amendment (2026-07-07) — Decision 2 reversed: no extractions
