# 0.45 — "The Front Door" (DX / docs information-architecture release)

**Status:** draft · **Target:** v0.45.0 (post-WWDC window, after 0.44 ships the recent PR backlog)
**Theme:** Developer experience. Turn an abundant-but-fragmented docs surface into one
navigable, visual, drift-free path in — and make that path provably compile from outside.

## Thesis

ManifoldKit does **not** have a docs *coverage* gap. It has a docs *coherence* gap.
There are already 8 `QUICKSTART-*.md` files, 12 DocC catalogs, plus
`WHY` / `POSITIONING` / `LAUNCH-BRIEF`, and almost zero open DX issues. The work for
0.45 is not "write missing docs" — it is:

1. **One front door**: a single ordered path `install → first token → BYO-UI → add tools/RAG/voice`.
2. **One DocC root**: an umbrella `ManifoldKit.docc` that ties the 12 standalone catalogs together (today they render as 12 disconnected archives with no "Start here").
3. **Kill the drift**: stale install pins, triplicated hero snippet, prose version skew.
4. **Wire the visuals**: the four launch SVGs already exist but are referenced by nothing.
5. **Prove it from outside**: extend the cold-start snippet gate so the front-door path can't silently rot.

Grounding research: `docs/plans/` worker reports (2026-06-07), built on the docs wave
that landed 2026-06-06 (#1639 positioning, #1658 developer-journey quickstarts,
`WHY-MANIFOLDKIT.md`, the `docs/images/{craft,product}/` reorg).

## Findings that scope the work

### Fragmentation & drift (from docs inventory)
- **No canonical index.** Only entry today is README's scattered link list. LAUNCH-BRIEF itself flags this twice ("no `docs/README.md` index tying the set together").
- **`WHY-MANIFOLDKIT.md` is an orphan** — 0 referrers, not even linked from README, yet it's the most newcomer-facing "why trust this" doc.
- **Hero `quickStart()` snippet is triplicated** — `WHY:102`, `LAUNCH-BRIEF:223`, `QUICKSTART:38`, in two contradictory forms (`.constant(false)` vs a real `$showModelManagement` binding).
- **BYO-UI snippet duplicated** — identical block in `QUICKSTART.md:283` and `QUICKSTART-BRING-YOUR-OWN-UI.md:24` (the #1658 promotion left the seed copy behind).
- **Install-pin drift** (repo is at 0.43.0): `QUICKSTART-IMAGE-GEN`, `-VIDEO-GEN`, `-VOICE` still pinned `0.36.0`; `SWIFTUI-MULTI-SESSION:270` pinned `0.37.0` **with no `x-release-please-version` marker** (will never auto-bump). Release Please `extra-files` is not covering these.
- **Prose version skew** — `POSITIONING` and `LAUNCH-BRIEF` body text both assert "v0.42.0".
- **Unenforced "supersedes" claim** — `SWIFTUI-MULTI-SESSION:4` claims to supersede QUICKSTART fragments, but QUICKSTART only links it as optional "see also".
- **Capability gaps in the path**: no `QUICKSTART-RAG.md` (RAG is shipped & marketed), no `docs/` MCP quickstart (tools doc bounces readers into source).

### DocC structure (from DocC audit)
- **No umbrella `ManifoldKit.docc`** — the re-exporting `ManifoldKit` target has no catalog. No cross-catalog navigation spine; one one-off cross-link only.
- **Zero DocC Tutorials** in the entire project — the step-structured quickstarts map cleanly onto `@Tutorial`/`@TutorialsCollection`.
- **`ManifoldFuzz.docc` and `ManifoldMCPHost.docc` have no root page** — their articles land orphaned in DocC's auto bucket.
- **Four backend targets have no catalog** — `ManifoldLlama`, `ManifoldCloud`, `ManifoldFoundation`, `ManifoldHuggingFace`; their docs live only as loose md (`llama-runtime`, `LLAMA_CONTRACT`, `LOCAL-GGUF`, `PROVIDER-BRIDGE`, `CLOUD-OAUTH`).
- **No `swift-docc-plugin`, no hosted site, no CI docs publish.** The only DocC-adjacent CI is `readme-snippets.yml`, which *compiles* snippets but renders nothing.
- **Content duplicated** between loose `docs/QUICKSTART-*.md` and module `.docc` articles (voice, appintents, image-gen, BYO-UI, multi-session) — two copies to keep in sync.

### Onboarding API & receipts (from onboarding audit) — these are GOOD, keep
- `ManifoldKit.quickStart()` is a single call; the README Hello World is ~25 lines, 3 imports, zero generics. Keep it as the canonical step 1.
- **Four cold-start gates already exist** (tiers 1–4) + `extract-snippets.sh` compiles **every** `swift` block in README, all `docs/QUICKSTART*.md`, and every `.docc` md. This is the receipt engine — extend it, don't rebuild it.
- **Receipt gap:** `WHY-MANIFOLDKIT.md` is NOT under the snippet sweep (extractor walks README + `QUICKSTART*` + `.docc` only).
- **Trait cliff:** with no backend traits enabled, `quickStart()` throws `noBackendsRegistered` at runtime, not compile time. Front-door docs must call this out loudly.

### Images (from onboarding audit)
- `docs/images/launch/` → `docs/images/product/` is a **rename** (same 4 filenames), `docs/images/craft/` is an empty `.gitkeep` placeholder.
- **All four SVGs are orphaned** — `layer-cake-hero`, `generationstream-backends-fan`, `vs-field-matrix`, `wwdc-backend-timing` are *specified* in LAUNCH-BRIEF §2 but embedded nowhere. LAUNCH-BRIEF item 4 ("layer-cake hero above the fold") is still open.

## Scope — workstreams

Shipped as **one docs/content PR + one DocC-infra PR** (stack-and-merge as a unit;
no phased P0→P5 split, per CI-cost policy). Pure-docs PR triggers no heavy compile;
the infra PR touches `Package.swift` + a new workflow, so it carries the cold-compile cost — keep it single.

### PR 1 — Front-door content & IA (docs-only, no code)
**WS1. Canonical index.** New `docs/README.md` with the ordered spine:
- *Start here:* `WHY-MANIFOLDKIT.md`
- *Getting started:* `QUICKSTART.md` → `SWIFTUI-MULTI-SESSION.md`; branch points `QUICKSTART-CLI.md`, `QUICKSTART-BRING-YOUR-OWN-UI.md`
- *Add a capability:* `QUICKSTART-TOOLS.md` → `QUICKSTART-APPINTENTS.md`, new `QUICKSTART-RAG.md`, `QUICKSTART-VOICE.md`, `-IMAGE-GEN.md`, `-VIDEO-GEN.md`
- *Reference / Security / Ship it:* group the rest; move `LAUNCH-BRIEF`, `SCOPE_DECISION`, `wwdc-2026-trait-stubs`, `QA-PRACTICES`, `voice-realtime-agent-design` out of the newcomer path (link from CONTRIBUTING).

**WS2. Wire `WHY-MANIFOLDKIT.md` into README** as the lead "why" link; add it to the snippet-compile sweep allowlist in `scripts/extract-snippets.sh`.

**WS3. De-duplicate.** One canonical hero snippet (the real-binding form), referenced from WHY/LAUNCH-BRIEF instead of recopied; collapse the duplicated BYO-UI block to live only in `QUICKSTART-BRING-YOUR-OWN-UI.md` with QUICKSTART linking to it.

**WS4. Kill drift.** Bump the three `0.36.0` pins + the `0.37.0` pin to current; add the missing `x-release-please-version` marker to `SWIFTUI-MULTI-SESSION:270`; add all four to `release-please-config.json` `extra-files`; refresh "v0.42.0" prose in POSITIONING/LAUNCH-BRIEF (or de-hardcode it).

**WS5. Fill path gaps.** New `QUICKSTART-RAG.md`; resolve the SWIFTUI-MULTI-SESSION "supersedes" claim (make QUICKSTART defer to it for session UI, or retract the claim).

**WS6. Wire the visuals.** Embed `layer-cake-hero.svg` above the fold in README; `generationstream-backends-fan.svg` in POSITIONING/WHY; finalize the `launch/`→`product/` deletion+add so git tracks the move cleanly. Decide `craft/` fate (populate or drop the placeholder).

**WS7. Document the trait cliff.** A prominent callout in QUICKSTART + the index: "no backend trait enabled → `quickStart()` throws `noBackendsRegistered` at runtime."

### PR 2 — Unified DocC root + hosted site (infra)
**WS8.** New `Sources/ManifoldKit/ManifoldKit.docc` umbrella catalog: root `ManifoldKit.md` (Overview ported from QUICKSTART + WHY) with a `## Topics` spine and cross-catalog `<doc:>` curation of the 12 module catalogs.

**WS9.** Convert the step-structured quickstarts (`QUICKSTART-CLI`, `-BRING-YOUR-OWN-UI`, `SWIFTUI-MULTI-SESSION`, `-IMAGE-GEN`, `-VIDEO-GEN`, `-VOICE`, `-TOOLS`, `-APPINTENTS`) into DocC Tutorials hung off the root (project has zero tutorials today). Loose `docs/*.md` become thin redirects or are retired to avoid the two-copies drift.

**WS10.** Add root pages to `ManifoldFuzz.docc` and `ManifoldMCPHost.docc`; backfill catalogs (or root curation) for the four backend targets so `llama-runtime`/`LLAMA_CONTRACT`/`LOCAL-GGUF`/`PROVIDER-BRIDGE`/`CLOUD-OAUTH` become DocC articles.

**WS11.** Add `swift-docc-plugin` (respect the Swift-tools-version ceiling — Xcode 26.x = Swift 6.2.x); new GitHub Pages workflow running `swift package generate-documentation --transform-for-static-hosting` deploying the unified root. **Add the workflow's own script path to its `paths:` filter** (self-validation footgun — see memory). Link the hosted site from README.

> PR 2 is optional for 0.45 if it overruns — WS8–WS10 (catalog structure) can ship without WS11 (hosting). The content PR (PR 1) is the must-have headline.

## Out of scope (explicitly)
- Diagnosability / `Manifold.diagnostics()` health check — that's a future "when it breaks, you know why" DX release, meaty enough to headline alone.
- Demo-as-living-docs (Glass Box scenario screenshots) — future visual release.
- Any API/behavior change. This release is docs + DocC infra only.

## Breaking-change budget
**Zero.** No public Swift API changes. Only doc moves, a new umbrella `.docc`, and CI wiring.

- [ ] `WHY-MANIFOLDKIT.md` reachable from README and under the snippet-compile sweep.
- [ ] No `docs/*.md` install pin lags the current release; `release-please-config.json` covers all of them.

- [ ] Hero snippet exists in exactly one canonical form; BYO-UI block exists once.
- [ ] All four product SVGs are embedded somewhere; none orphaned. `launch/`→`product/` move is a clean git rename.
- [ ] `QUICKSTART-RAG.md` exists; RAG appears in the spine.
- [ ] (PR 2) `swift package generate-documentation` builds the unified root with no orphaned articles; Fuzz/MCPHost have root pages.
