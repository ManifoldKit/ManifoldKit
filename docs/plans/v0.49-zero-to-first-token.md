## 0. Why this release (evidence)

1. **The post-split first-launch is a hardcoded guess.** `QuickStartSeed.recommendedSmallModel()` (`Sources/ManifoldKit/QuickStartSeed.swift`) is pinned to Qwen3-0.6B-Q4_K_M (~400 MB) regardless of device. A machine with 64 GB unified memory and an M-series GPU gets the same 0.6B model as a base iPhone. The infrastructure to do better already ships (see §0.3) — it is simply not wired to the seed path or surfaced to hosts.
2. **The backlog points here.** #1782 is the largest, most product-relevant open ask, and the umbrellas (#753/#754/#755) are closed — there is no competing in-flight feature train. The recommender is on-thesis for Pillar 1 (full-stack altitude) and the "AI made writing code easy; keeping the project alive hard" framing: model-selection-on-real-hardware is exactly the unglamorous integration work hosts re-derive badly.
3. **~80% is expose-and-compose, not a new probe layer.** The device/catalog primitives already exist and are public: `DeviceProfile` + `AppleSiliconBandwidth` (M1–M4 bandwidth table), `ModelLoadPlan` + `ModelCapabilityTier` fit verdicts (`.allow/.warn/.deny`), `GGUFKVCacheEstimator`/`ModelInfo.estimatedKVBytesPerToken`, measured `ModelBenchmarkResult` + `BenchmarkCache`, `ModelFitScorer` + `ModelUseCase.weights`, and `FoundationBackend.isAvailable` as a zero-cost Tier-0 check. The net-new is small (see §2) — this is a finishing move, low risk for a minor.
4. **#1710 multimodal is not available to ship.** WWDC 2026 announced "natively multimodal AFM 3," but the Phase-0 SDK probe (§4) found **no image-input surface in the shipping SDK**. Committing the release to it would have stalled; investigating first cost one probe.

## 0.5. The decision this plan forces

0.49.0 is **already cut** (#1779 open) with the recommender *library* as its only feature. So the real question is not "what is the 0.49 headline" — it's decided — but **"does 0.49.0 ship the headline as a primitive, or as an experience?"** Three options:

- **(a) Ship 0.49.0 as-is.** The scorer is a clean library win; merge #1779, do the completion work (Workstream A below) in 0.49.1. Lowest risk; the "zero to first token" story is *available* but not *default*.
- **(b) Hold #1779, land the seed+UI wiring first.** 0.49.0 then delivers the full experience: first-launch actually picks the right model. Higher narrative payoff; costs one more feature PR + CI before release. **Recommended** — the wiring is small and additive, and a recommender nothing calls is a weak headline.
- **(c) Hold #1779 for the full bundle (A + B + guardrail flag).** Most compelling release, but largest hold; B's payoff is companion-gated (§3).

## 4. #1710 multimodal — Phase-0 probe result (DEFER)

Direct SDK inspection (2026-06-13, Xcode 26.5 build 17F42, FoundationModels `-user-module-version 1.5.2`, both macOS and iOS swiftinterfaces, identical):

- `Transcript.Segment` is still `case text | case structure` — **no `image`/`attachment` case**; neither payload struct carries `Data`/`CGImage`/`CVPixelBuffer`.
- `Prompt` inits: `init(segments:…)` and `init(_ : some PromptRepresentable)` — **no `Data`/`CGImage` initializer**. `PromptRepresentable` conformers are `String`, `Prompt`, `Optional`, `Array` only.
- `GenerationOptions`: `sampling`/`temperature`/`maximumResponseTokens` — no vision knob. `SystemLanguageModel.UseCase`: `.general`/`.contentTagging` only.
- Whole-word sweep for `image|cgimage|pixelbuffer|vision|multimodal|ocr` → zero hits (the lone `logFeedbackAttachment` is telemetry, not model input).

**Disposition:** keep `supportsVision: false`. Refresh the `FoundationBackend.swift` doc comment to record that module **1.5.2 also lacks the surface** (the comment currently references 1.4.34). Re-probe trigger for 0.50: a later Xcode bumps the module version *and* adds an image case to `Transcript.Segment` or a `PromptRepresentable` image conformer. No code change this release beyond the doc note.
