**Status:** APPROVED 2026-06-12 — executing. All §7 decisions resolved to the recommended option: (1) split `ManifoldOllama`+`ManifoldCloudSaaS` products; (2) static `register(with:)` + `quickStart(backends:)`; (3) loud-inside-silent shim; (4) build-modes/SBOM discontinuity accepted; (5) MCP tests on every lane accepted; (6) two companion repos; (7) AnyLanguageModel product in A5; (8) HuggingFace retired in C2; (9) README snippet = core + manifold-llama + `quickStart(seed:)`. ## 0. Why this release (evidence)

1. **The trait architecture fails in ways we cannot fix.** #1737 investigation (2026-06-12) proved the "HuggingFace-trait-off consumers can't build" failure is *not* a 0.46.0 regression: gating byte-identical across 0.45→0.46, same error hit Fireside CI 2026-05-07, five faithful clean-state repros all pass. Root cause is upstream SwiftPM: `.when(traits:)` conditions on product-dependency edges are evaluated inconsistently between resolution and `--build-tests`/`--filter` graph derivation (swiftlang/swift-package-manager#8350, #8398, #9286). Every trait-gated `.product` edge (`MLX`, `LlamaSwift`, `Hummingbird`, …) has the same latent shape.
2. **Xcode trait support is broken through 26.x** (Apple forums 820911); pointfreeco — the other major trait adopter — now tells consumers to make wrapper packages.
3. **The breaking window is open, and the break auto-delivers anyway.** SwiftPM `from: "0.47.0"` = `0.47.0..<1.0.0` — there is **no 0.x special case** (verified empirically by two independent reviewers; the #1737 Fireside evidence is itself an instance of a `from:` consumer auto-adopting a minor). Consumers will receive v0.48 on their next clean resolve whether we ship one breaking minor or two — which is the strongest argument for shipping **one**.
4. **The seam is *nearly* ready — but not proven.** P2/P3 merged; `BackendRegistrar`'s declared API is public. Review found the undeclared surface is not: see §3 B-work and §5 gate.

**#1737 disposition:** close as upstream-SwiftPM + consumer-CI-state (Fireside's force-clean step should also `rm -f Package.resolved`). Do NOT ship the 2-line defensive ungate (whack-a-mole). Add the diagnosis to #1749 as evidence.

**Versioning (corrected per review — SwiftPM has NO 0.x caret rule):**
- `from: "0.47.0"` consumers resolve `0.47.0..<1.0.0` → **v0.48 auto-delivers**. Release notes lead with this; README gains "pin `.upToNextMinor` if you want opt-in upgrades pre-1.0".
- Companions pin core with **`.upToNextMinor(from: "0.48.0")`** (not `exact` — core patches must flow; not `from:` — a seam-breaking core 0.49 would silently float in). This is what makes the pin-bump-per-core-minor + canary mitigation correct.
- Consumer-side behavior when core 0.49 ships before the companion pin-bump: **no error** — resolution silently intersects to core 0.48.x (staleness, not breakage). The compatibility table lives in the **core** README too (that's the repo consumers look at), mirrored in each companion.
- Companions start at 0.1.0. At ManifoldKit 1.0, companions ship 1.0 in the same train; lockstep cost collapses.

**Consumer migration (no cross-repo shim is possible — core cannot re-export companion symbols without recreating the dependency; and module-name tombstones are impossible because companions keep the `ManifoldMLX`/`ManifoldLlama` module names):**

```swift
// Before (v0.47): traits, implicit discovery
.package(url: ".../ManifoldKit", from: "0.47.0")   // MLX/Llama on by default

// After (v0.48):
.package(url: ".../ManifoldKit", from: "0.48.0"),
.package(url: ".../manifold-mlx", from: "0.1.0"),
// target deps: "ManifoldKit", .product(name: "ManifoldMLX", package: "manifold-mlx")
```
```swift
import ManifoldKit
import ManifoldMLX

let kit = try await ManifoldKit.quickStart(backends: [MLXBackends.self])  // new B2 API
```
(All companion-referencing snippets in README/QUICKSTART/DocC need `swift,no-build` fencing — readme-snippets compiles every swift block against core and the companion import cannot resolve there.)

8 core PRs total (A1–A5, B1–B3) + C2; ~6,000–6,500 billed CI minutes green (vs ~9,000–10,000 unconsolidated), assuming the `--profile local` gate holds the re-run tax down.

**Go/no-go — RESULT (2026-06-12, B3): `scripts/split-proof.sh` → PROOF: PASSED for both families.** manifold-llama: 10 source files compiled against core's trait-less products (`ManifoldInference`/`ManifoldHardware`/`ManifoldContract` + exact-pinned llama.swift), 7 contract tests executed (2 hardware-gated skips). manifold-mlx: 34 source files (ManifoldMLX + vendored FluxSwift/StableDiffusion), 7 contract tests executed (2 skips). **Zero seam gaps found** — B2 (#1766) had published the complete surface; no core promotions were needed in B3. Non-vacuity and gate-strip guards sabotage-verified (a surviving `#if` gate or a 0-tests-executed run fails the script). The C-stream is GO; C1 re-runs the same script when bootstrapping the real repos.

**Go/no-go.** Original plan offered (a) split as v0.49 honoring a "2 stable releases" calendar gate vs (b) one combined v0.48. Review resolved this:
- The calendar gate's premise is already falsified — the seam had undeclared leaks (B2 list) that no amount of calendar time would surface; only an out-of-package compile does.
- The break auto-delivers to `from:` consumers (§4) — so option (a) means **two** auto-adopted break events; (b) means one.
- **Decision: (b) — one release — gated on the B5 proof instead of the calendar.** If B1/B2 surface seam changes too large to freeze confidently, fall back to (a) automatically: ship A+B as v0.48 (still a meaningful `feat!:` — 9 traits retired), split as v0.49 after the tripwire has watched one release.

**Release-train guardrails (Release Please):** `bump-minor-pre-major: true` means the mixed `feat:`/`feat!:` train correctly collapses to one 0.48.0 minor with a breaking-changes section. Two traps: (i) the release PR opens after A1 merges and sits open for weeks — label it `do-not-merge: v0.48 train` immediately; CHANGELOG rewrite is a C3 step; (ii) hotfix lockout — any 0.47.x patch during the train ships from a `release-0.47` branch with a manual tag.

## 7. Open decisions (maintainer)

1. **Cloud product shape:** split `ManifoldOllama` + `ManifoldCloudSaaS` (recommended — only way the FIPS "SaaS code not present" claim and build-modes procurement evidence survive) vs the split doc's singular "Cloud".
2. **Registration shape:** static `BackendRegistrar.register(with:)` + new `quickStart(backends:)` (recommended) vs registrar injection at `ManifoldBootstrap`.
3. **`ManifoldBackends` shim:** recommended **loud-inside-silent** — keep one deprecated Foundation+Cloud-only release, with `@available(*, deprecated, message: "... see docs/MIGRATION-0.48.md")` on `DefaultBackends.register`/`registrars` + the B2 runtime no-backend warning. (Fireside-shaped consumers compile clean against the shim and would otherwise silently lose all local inference.)
4. **build-modes semantics post-traits:** per-mode `--product` builds keep the symbol-audit series; artifact shape changes — confirm the discontinuity note. Core SBOM also narrows at C2 (companions get their own provenance workflows).
5. **MCP test cost:** retired trait ⇒ ManifoldMCPTests on every lane — accept (recommended) or path-filter.
6. **Two repos vs one `manifold-backends` monorepo** (plan assumes two, per #1749).
7. **AnyLanguageModel product in A5 vs defer.**
8. **HuggingFace trait:** retired in C2 with the heavy set (swift-nio drag via EventSource is split-era); its conditional `.product` edge is the canonical #1737 hazard — confirm it shouldn't become always-on in A instead.
9. **README canonical first-run snippet post-split:** on n-1 platforms (macOS 15/iOS 18) a core-only install has zero usable backends out of the box (no Foundation, no local; cloud needs an endpoint). Recommend core + manifold-llama + `quickStart(seed:)` as the honest 3-step.

## 8. Top risks

1. **Undeclared seam surface beyond what review found** (`package` symbols, `@_exported` chains, compile-time reflection). Mitigation: B2 grep-sweep + **B5 out-of-package compile proof before go/no-go** — the gate is the proof, not the calendar.
2. **Silent consumer degradation** — dead fail-fast guard, no-op starter seed, shim-that-compiles-but-can't-infer, unfiltered model auto-selection. Mitigation: all four are named B2 deliverables gating C.
3. **Empty-module companions with green CI** (whole-file `#if` gates survive the copy). Mitigation: C1 de-gate step + non-vacuity tripwire + symbol assertion.
4. **C3 window** — consumers auto-resolve a core with no local inference before companion tags exist. Mitigation: scripted single-sitting checklist (§4 C3).
5. **Release-train mechanics** — premature release-PR merge; hotfix lockout. Mitigation: `do-not-merge` label; `release-0.47` branch policy.
6. **Pre-1.0 pin staleness** (silent intersection to core 0.48.x when 0.49 ships). Mitigation: `.upToNextMinor` companion pins + scripted pin-bump + weekly canary + release-time `repository_dispatch`; compatibility table in core README.
7. **CI cost** — train ~6,000–6,500 billed min consolidated; ongoing canary ~1,200/month (weekly) vs ~9,000 (nightly). Mitigation: 8-PR consolidation, full local gate before every push, weekly canary cadence.
8. **#982 regression** via Tools retirement (A3) — local Xcode scheme check before merge.
